# 城市视角连续浏览边界审计

日期：2026-10-23

范围：城市详情、城市历史时间轴、城市政权列表，以及事件／遗产／政权详情抽屉之间的导航连续性。只审查城市相关组件和测试，不修改 `RelationshipGraph.tsx`、`knowledge-coverage.ts` 或人员数据。

## 审查结论

本轮没有发现需要改动城市组件的真实缺口。现有链路已经形成：

`今天的城市（现代位置） → 城市历史时间轴／政权列表 → 历史政权、事件、遗产 → 50vw 详情抽屉 → 返回上一个实体`

具体依据：

1. 城市详情由 `InfoPanel` 展示现代名称、现代行政参照、坐标和首都／政治中心角色，并嵌入 `StudyRelationsPanel`。
2. `CityHistoryTimeline` 同时生成地点、政权、人物、事件和遗产节点；节点统一通过 `onOpenEntity` 进入详情抽屉。
3. 城市政权列表可打开政权详情；政权详情可继续进入其事件、人物和遗产关系。
4. `App.openDetail` 维护实体返回历史，因此从城市打开事件或遗产后，可以返回城市抽屉继续浏览。
5. 事件和遗产详情分别由 `EventDetail`、`HeritageDetail` 承载；本轮未发现城市入口绕过详情组件或丢失实体类型／ID 的问题。

## 本轮新增验证

新增应用级回归测试覆盖长安路径：

1. 从历史状态目录进入唐，再进入长安城市详情。
2. 从城市历史时间轴打开“唐在长安建立”事件详情。
3. 使用“返回上一个实体”返回长安城市详情。
4. 从同一城市时间轴打开“大明宫遗址”遗产详情。

该测试验证城市视角不是只能单向打开实体，而是可以在“城市 → 事件 → 城市 → 遗产”之间连续浏览。

## 保留边界

- 城市时间轴仍是精选历史层，不宣称穷尽所有事件、人物或遗产。
- 跨政权、共享转折和叠压遗产继续保留在城市视角，不强行归入单一政权。
- 本轮不增加城市事实、不补人物关系、不改变覆盖审计规则。
