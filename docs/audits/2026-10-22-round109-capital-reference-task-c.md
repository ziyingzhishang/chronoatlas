# 第109轮首都链路任务 C 审计

## 范围与硬性边界

本轮只处理以下 7 个共享候选：秦—楚汉之争、唐—洛阳行幸、后梁五代转折、东周东迁、北宋建政重复节点、后凉姑臧遗产、后周开封遗产。

安全闭合必须同时满足：

1. 首都阶段明确提供政权、地点与有效年代；
2. 事件或遗产拥有可以单独引用的端点；
3. 事件详情或遗产详情明确支持目标政权，而不是只提供同城关系；
4. 地点与首都阶段一致，且事件年份或遗产阶段与首都阶段重合；
5. 语义上属于目标政权的独立事实，不重复既有建政叙事，也不把跨政权遗产拆成单一政权遗产。

## 本轮结论

7 项均未达到安全闭合条件，本轮不修改政权详情中的 `eventIds` 或 `heritageIds`，不新增事件与遗产节点。

## 逐项核验

| 候选 | 端点核验 | 分类 | 结论 |
|---|---|---|---|
| 秦—楚汉之争 | `chu-han-contention` 的地点含咸阳，但 `polityIds` 同时包含 `qin`、`han_western`，时间从前206年延续至前202年；咸阳只是秦亡与分封背景的一部分 | `shared-transition-event` | 不将共享战争节点补入秦首都链路；前206年秦政权覆亡与汉方后续承接不能压成秦专属首都事件 |
| 唐—洛阳行幸 | `court-moves-luoyang` 同时关联唐与后梁，地点同时含长安、洛阳，904年迁廷是后梁建立前的权力转移 | `shared-transition-event` | 不将共享迁廷节点补入唐首都详情 |
| 后梁五代转折 | `five-dynasties` 同时关联唐与后梁，且已有 `later-liang-five-dynasties-founded` 作为后梁建政的独立端点 | `shared-transition-event` | 不重复写入 `five-dynasties`，避免将五代分期叙事重复为后梁首都事件 |
| 东周东迁 | `zhou-eastward` 同时关联西周与东周，前770年是王室迁徙与分期转换节点，不是可脱离西周背景的东周重复建政事件 | `foundation-stage-boundary` | 不把分期/迁都节点再次写入东周首都事件链 |
| 北宋建政重复节点 | `song-founded` 虽明确关联北宋、开封与960年，但北宋详情已有 `northern-song-founded`；两者表达同一建政事实 | `duplicate-event-node` | 不新增重复引用 |
| 后凉姑臧遗产 | `guzang-baita-temple-site` 的 `associatedPolities` 同时包含前凉、北凉、后凉；401—439年的遗产阶段不能单凭姑臧同城归给386—403年的后凉 | `cross-polity-heritage` | 不将跨政权遗产补入后凉详情 |
| 后周开封遗产 | `kaifeng-northern-song-city-site` 的遗产详情覆盖后梁、后晋、后汉、后周、北宋，主体阶段为960—1127年的北宋城市层 | `cross-stage-city-layer` | 不用跨阶段城市考古层反推后周专属遗产 |

## 回归边界

对应测试：`src/data/capital-reference-round109.task-c.test.ts`。

测试固定以下不变量：共享事件必须保留多政权归属；重复节点不得取代已有独立建政事件；共享或跨阶段遗产不得直接写入目标政权详情。后续只有在取得更细的事件参与端点、分期遗产证据或独立政权归属后，才重新评估闭合。
