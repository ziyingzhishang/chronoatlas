# 地图状态卡、搜索入口与折叠时间条设计

## 背景与目标

地图左上角的当前状态入口、历史事件搜索框和底部时间控制器承担同一件事：帮助读者确认“我正在看哪个年份、哪个时代，以及如何继续移动时间”。现有界面中，年份辨识度不足，状态入口没有直接显示朝代与距今年数；搜索框与状态卡在高度和间距上缺少统一；时间控制器收起后，顶部控制条仍没有承担必要的时间阅读与播放操作。

本次调整建立一套连续的信息层级：左上角状态卡负责识别当前历史时点，搜索框负责跳转历史转折，底部折叠时间条负责最少步骤的时间移动。调整不得改变地图年份、镜头、专题分栏、时间轴范围或现有目录与搜索行为。

## 一、历史状态卡

### 信息结构

状态卡第一行按以下顺序展示：

1. 当前年份，例如“800年”；
2. 当前代表性朝代或政权，例如“唐”；
3. 当前时间视窗标签，例如“王朝至今”；
4. 右侧独立标签，例如“距今1226年”。

第二行保留当前时间轴视窗，例如“当前视窗 · 前2070年—2026年”。

年份是第一视觉层级，使用约 20px 字号和等宽数字特性；朝代和时间段使用约 12—13px；距今标签使用紧凑胶囊样式。上下两行之间保持明确但不松散的行距，卡片四周至少保留 12px 水平、10px 垂直内边距。

### 朝代选择规则

- 优先显示当前年份在中国历史范围内的中央或主要政权。
- 若同年存在多个政权，沿用当前目录/地图状态中已经确定的代表性显示顺序，不临时创造新的历史排序规则。
- 没有可显示的代表性朝代时使用可读的时期名称；仍无结果时省略该标签，不显示内部 ID 或占位代码。
- 朝代标签只用于帮助定位当前时代，不暗示同年只有一个政权。

### “距今”计算规则

- 以客户端当前公历年份实时计算，当前验收基准年份为 2026 年。
- 公元年份：`当前年份 - 历史年份`。
- 跨越公元前后时排除不存在的公元 0 年，例如公元前 221 年显示“距今2246年”。
- 当前年份显示“今年”；未来年份显示“距今尚有 X 年”。
- 计算函数独立于 React 组件，并覆盖公元前、公元后、当前年和未来年测试。

## 二、搜索入口

- 状态卡和搜索输入框使用相同的外部高度基准；在本轮设计中桌面和常见平板采用 64px，窄屏可以通过响应式变量统一缩减，但二者必须始终等高。
- “查找历史转折”保留为可访问名称，不再单独占据视觉高度；视觉界面只显示输入框及占位提示。
- 状态卡与搜索框之间固定保持 18px 垂直间距，不使用组件内部偶然形成的行距。
- 搜索弹层仍从输入框下方展开，目录弹层仍由状态卡打开；两者继续互斥。
- 输入框的左右内边距不少于 12px，文字垂直居中，聚焦样式不能改变组件高度或推动地图。

## 三、折叠时间条

### 收起状态

收起状态不再渲染一段被裁切的完整时间轴正文，而是由顶部控制条直接承担必要功能：

- 左侧：拖动柄或密度切换入口、当前年份、当前朝代；
- 右侧：上一年、播放/暂停、下一年、进入刻度视图和展开视图的入口；
- 非移动端停靠状态可以保留“悬浮”操作；空间不足时优先隐藏文字型布局模式名称，保留有明确无障碍名称的操作按钮；
- 播放状态与完整时间轴共用同一个 `isPlaying` 和 `onPlayToggle`，不得产生两套状态；
- 上一年和下一年沿用现有无公元 0 年的年份移动规则。

收起后的控制器应是真正的单行控制条，正文容器不可继续占据可见高度。其目标高度为 48—52px，并计入安全区内边距。

### 紧凑与展开状态

- 紧凑和展开状态继续复用现有 `Timeline` 内容及时间范围、事件标记和语义视图逻辑。
- 顶部控制条仍显示密度与停靠/悬浮操作，但避免再次显示与正文完全重复的播放控件。
- 从收起切换到紧凑或展开，以及重新收起，都不改变当前年份、播放状态、时间视窗或地图镜头。

## 四、组件边界与数据流

### 独立逻辑

- 新增纯函数负责距今年数和可读标签计算。
- 新增纯函数或选择器从当前历史状态中取得代表性朝代名称；它只返回可读名称，不把领域对象或内部 ID交给展示组件。
- `App` 组合状态卡需要的年份、朝代、时间视窗与距今标签。

### 状态卡

状态卡内部拆为语义明确的子元素，但继续保留单一按钮行为和现有目录开关。整个卡片仍具有“当前历史状态”的可访问名称，并通过 `aria-expanded` 表达目录状态。

### 时间控制器

`TimeController` 在收起状态渲染专用的 `CollapsedTimeControls`；紧凑和展开状态渲染原有 `Timeline`。两种表示共享同一组年份和播放回调，避免同步副本。

## 五、响应式规则

- 宽屏和横向平板：状态卡第一行保持单行，距今标签靠右；搜索框等高并保持 18px 间距。
- 809×934：必须完整显示四类状态信息，底部收起条容纳年份、朝代、播放和密度操作，不遮挡地图归属信息。
- 390×844：状态卡允许时间段缩写或省略，年份和距今信息优先保留；折叠时间条可以隐藏“悬浮”等布局模式文字，但保留上一年、播放、下一年和展开入口。
- 手机横屏或高度不超过 500px：状态卡和搜索框使用同一紧凑高度；底部时间条保持单行，不展开正文。
- 专题真实分栏打开时，所有宽度计算以 `MapPane` 容器为准，不使用整个浏览器宽度，时间条不得进入专题栏。

## 六、可访问性

- 状态卡的视觉拆分不破坏其按钮语义。
- 搜索框继续具有“搜索历史事件”的可访问名称。
- 折叠时间条所有图标或短标签按钮必须提供完整的 `aria-label`。
- 播放按钮根据状态读作“播放”或“暂停”。
- 密度切换按钮通过 `aria-expanded` 与受控内容关联。
- 键盘操作、焦点顺序和至少 44px 的移动端触控目标保持可用。

## 七、测试与验收

### 单元与组件测试

- 距今计算覆盖公元 800 年、公元前 221 年、当前年与未来年，验证无公元 0 年。
- 状态卡按“年份—朝代—时间段—距今”顺序输出，缺少朝代时不泄露内部 ID。
- 搜索框和状态卡使用同一高度变量，间距为 18px。
- 时间控制器收起时不渲染可见的完整时间轴正文，并显示年份、朝代、上一年、播放和下一年操作。
- 播放、逐年移动、密度切换均调用现有回调；展开与收起不重置年份或视窗。
- 中英文界面均输出可读文本，不泄露内部标识。

### 浏览器验收

- 在 809×934、390×844、1440×900 和手机横屏下检查状态卡、搜索框及折叠时间条。
- 状态卡和搜索框等高，垂直间距为 18px，文字不贴边、不截断。
- 公元 800 年显示“唐”和“距今1226年”。
- 折叠时间条为单行；播放后按钮切换为暂停，年份正常前进；停止后状态一致。
- 详情分栏打开、调整分隔线和关闭详情后，时间条始终限制在地图栏内。
- 页面无横向滚动，地图导航、比例尺和归属信息不被遮挡。

## 八、范围外事项

- 不调整历史数据本身，不新增政权优先级研究结论。
- 不改变搜索结果、目录内容或专题详情的信息架构。
- 不重新设计紧凑与展开时间轴的事件标记和语义缩放。
- 不修改地图镜头、疆域几何或播放速度。
