# 山河年轮历史知识图谱详情抽屉与长安完整示范设计

## 1. 目标

山河年轮的地图负责定位，时间轴负责观察历史变化，摘要卡负责快速理解，详情抽屉负责深入学习，关系图负责发现关联，来源区负责判断可信度。

本设计解决当前人物、事件、遗产信息不完整且无法深入交互的问题，建立统一的实体详情抽屉和可扩展的历史知识图谱模型。第一阶段以长安／西安为完整示范，验证后复制到洛阳、南京、北京、开封、成都、杭州及全部政权。

## 2. 范围与边界

### 本期包含

- 政权、地点、人物、历史事件、遗产五类实体的统一详情入口。
- 右侧约 50% 宽度的桌面抽屉；移动端全屏抽屉。
- 摘要卡与详情抽屉分层展示。
- 人物的君臣、亲属、师承、联盟、对立等关系。
- 事件的参与者、阶段、原因、结果、影响和地点关联。
- 遗产的历史关联、建造沿革、现状、现代位置和考古不确定性。
- 时间、来源、置信度、不确定性和观察视角。
- 长安／西安的完整示范数据和验收指标。

### 本期不包含

- 一次性声称覆盖全部历史人物和全部史实。
- 自动从低可信资料推导人物关系或历史疆域。
- 复杂社交网络式的自由编辑。
- 用户贡献、审核后台和多用户协作。
- 大规模图片版权采集；媒体资源先预留接口。

## 3. 交互设计

### 3.1 信息层级

```text
地图 / 时间轴
  -> 摘要信息卡
      -> 点击实体
          -> 50% 宽度详情抽屉
              -> 点击关联实体
                  -> 抽屉内导航或新一层详情
```

摘要卡只展示名称、年代、核心结论、关系数量和关键节点；完整正文、关系、时间线和来源进入抽屉。

### 3.2 详情抽屉

桌面端宽度为视口 50%，最大宽度 760px，从右侧滑入；背景保留地图并加遮罩。支持关闭按钮、Escape、焦点回收和返回上一个实体。移动端使用全屏抽屉。

统一状态：

```ts
type DetailEntity =
  | { type: 'polity'; id: string }
  | { type: 'place'; id: string }
  | { type: 'person'; id: string }
  | { type: 'event'; id: string }
  | { type: 'heritage'; id: string };
```

抽屉统一分为：概览、时间线、关系、地点／遗产、来源与考据。没有数据时显示明确的“暂无已收录资料”，不使用空白区域或推测性文本。

### 3.3 关系图交互

政权视角默认展示政权、人物和遗产三层关系。关系图同时提供文本清单，确保键盘、读屏和窄屏可用。点击节点打开对应详情抽屉；关系类型和有效年份可筛选。

城市视角以城市时间轴为主：不同年代的政权、人物、事件和遗产作为节点，点击节点进入相应详情。

## 4. 领域数据模型

### 4.1 实体

保留现有 `Polity`、`Place`、`Person`、`HistoricalEvent`、`HeritageAsset`，但为详情增加专门的扩展结构，不把所有长文本塞进基础实体。

人物详情：

```ts
interface PersonDetail {
  personId: string;
  biography: string;
  offices: PersonOffice[];
  aliases: string[];
  keyEvents: string[];
  sourceIds: string[];
  uncertaintyNote?: string;
}
```

事件详情：

```ts
interface HistoricalEventDetail {
  eventId: string;
  participants: EventParticipant[];
  polityIds: string[];
  causes: string[];
  consequences: string[];
  phases?: EventPhase[];
  locationIds: string[];
  relatedEventIds: string[];
  sourceIds: string[];
  uncertaintyNote?: string;
}
```

遗产详情：

```ts
interface HeritageDetail {
  heritageId: string;
  modernLocation: string;
  historicalAssociations: string[];
  constructionHistory: HeritagePhase[];
  associatedPeople: string[];
  associatedPolities: string[];
  associatedEvents: string[];
  survivingFeatures: string[];
  presentDayValue: string;
  sourceIds: string[];
  uncertaintyNote: string;
}
```

### 4.2 图谱关系

统一使用带时间和来源的 `HistoricalClaim` 表达关系。关系谓词采用受控词表：

- 人物：`parent-of`、`child-of`、`spouse-of`、`sibling-of`、`teacher-of`、`student-of`
- 政治：`served`、`appointed`、`succeeded`、`founded`、`ruled`、`rebelled-against`
- 事件：`participated-in`、`caused`、`resulted-in`、`occurred-at`
- 遗产：`commissioned`、`left-heritage`、`located-at`

每条关系必须带有效年代、日期精度、观察视角、证据类型、置信度和来源。亲属关系与君臣关系必须有方向，不能只存无向边。

## 5. 长安／西安完整示范

首批目标：

- 15 个左右历史政权或政治阶段
- 30–50 位重要人物
- 100–200 条人物及人物—政权关系
- 30–60 个关键事件
- 20–30 个遗产与城市记忆节点
- 每个核心节点至少 1 个来源；高争议关系必须标注不确定性

建议时间层：西汉、新、东汉过渡、前赵、前秦、后秦、北魏／西魏、北周、隋、唐，以及现代西安参照层。

## 6. 质量与证据

项目不宣称“全部历史事实完整”，而宣称“在定义范围内可追溯、可扩展、可标注缺口”。每个实体和关系进入覆盖矩阵，记录：

- 是否有来源
- 是否有时间范围
- 是否有古今地点映射
- 是否有关系方向
- 是否完成交叉核验
- 是否存在争议

数据质量等级：`draft`、`source-checked`、`cross-checked`。UI 必须展示低置信度和不确定性，不把推断显示为确定事实。

## 7. 技术架构

- `domain/types.ts`：稳定的基础实体和断言类型。
- `domain/detail-views.ts`：按实体构建详情视图模型。
- `domain/relationships.ts`：关系查询、分类、时间过滤和图谱邻接索引。
- `data/*-details.ts`：人物、事件、遗产详情目录。
- `components/EntityDrawer.tsx`：统一抽屉容器和导航栈。
- `components/EntitySummaryCard.tsx`：摘要卡。
- `components/PersonDetail.tsx`、`EventDetail.tsx`、`HeritageDetail.tsx`：实体详情内容。
- `components/RelationshipGraph.tsx`：图形与文本双模式关系网络。
- `components/CityHistoryTimeline.tsx`：城市历史时间轴。

详情视图从目录和断言构建，不让组件直接拼接原始数组。数据缺失、实体不存在和关系无来源都要返回可解释状态。

## 8. 验收标准

- 点击摘要卡可打开对应实体抽屉。
- 抽屉在桌面端约占 50% 宽度，移动端自适应全屏。
- Escape、关闭按钮、返回按钮均可用。
- 从人物、事件、遗产和关系图节点可跳转到其他实体。
- 人物抽屉能区分亲属、君臣、联盟和对立关系。
- 事件抽屉能展示参与者、过程、结果、影响和来源。
- 遗产抽屉能展示历史关联、今日状态和不确定性。
- 关系查询按年份过滤，不显示超出有效期的关系。
- 图形关系网络同时提供文本替代内容。
- 长安示范达到约定数量和来源覆盖率。
- 全量测试、构建、语言审计和数据完整性检查通过。
