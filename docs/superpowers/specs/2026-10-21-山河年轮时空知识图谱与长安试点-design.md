# 山河年轮时空知识图谱与长安试点设计

## 目标定位

“山河年轮”定义为一个带证据、时间和不确定性的历史时空知识系统，而不是单纯的历史疆域地图。

用户应能从政权、城市、人物、事件、遗产和史料六种入口进入同一套知识网络，并理解：在什么时间、从什么视角、依据哪些材料，可以怎样解释一段历史。

## 核心学习视角

### 政权视角

回答：这个政权为什么建立、由谁建立、如何扩张和治理、如何衰亡，以及它与首都、人物、事件和遗产的关系。

### 城市视角

回答：今天的城市经历过哪些政权，为什么成为政治中心，曾发生哪些事件，哪些历史遗存仍可见。

### 人物视角

回答：人物在什么政权、城市和关系网络中行动；其身份、评价和史料记载如何随时间变化。

### 遗产视角

回答：建筑、城址、陵墓、碑刻、文物或博物馆与哪些政权、人物、事件有关，现存状态与历史状态有何区别。

### 史料视角

回答：一条结论来自哪些材料，材料之间是否冲突，项目采用了哪一种解释，哪些部分仍有争议。

## 知识模型

### 内容与代码边界、存储演进

目前走查发现，部分内容类信息与应用代码放在一起。知识模型应从一开始就把领域内容视为独立数据，而不是组件或业务逻辑中的常量：政权、地点、人物、事件、遗产、史料、断言、别名、叙述文本及其关系，均应有稳定 ID、明确结构和可校验的引用关系。界面与领域逻辑通过数据访问/查询接口读取内容，不直接依赖某个具体文件路径或硬编码数据模块；地图和页面组件只负责呈现，不承载可编辑的史实内容。

第一阶段可继续使用仓库内的 TypeScript/JSON 等文件作为轻量存储，但文件只是当前适配器，不是领域模型本身。目录和格式应便于未来把结构化实体、关系、索引及查询迁移到数据库，同时将长文本、图片、地图几何、扫描件等大体积或媒体文件放在文件/对象存储中；数据库记录通过稳定 ID 或受控 URI 引用文件，并保留来源、许可、校验值和版本等元数据。应用应通过统一仓储/数据服务接口取数，避免未来迁移时重写视图与领域规则。

迁移到数据库是后续可选的存储实现，不属于当前试点的前置条件。首阶段应优先明确实体/断言 schema、ID 与引用规则、内容与代码目录边界、文件资源引用约定和数据校验方式；当协作编辑、数据规模、检索或并发写入需求确实超出文件存储能力时，再评估数据库类型和迁移方案，不预设必须采用某一种数据库。

### 实体节点

- `Polity`：政权、王朝、王国、地方政权、部落联盟等。
- `Place`：城市、都城、历史区域、战场、山川、交通节点和遗址位置。
- `Person`：君主、官员、将领、思想家、宗教人物、地方领袖等。
- `Event`：建国、战争、迁都、改革、政变、会盟、灭亡等。
- `HeritageAsset`：建筑、城址、宫殿、陵墓、碑刻、出土文物、博物馆和纪念场所。
- `Source`：史书、考古报告、碑刻、地方志、现代研究和图像资料。
- `Claim`：带时间、证据、视角和置信度的历史断言。

### 关系节点

实体之间的关系必须独立建模，而不是全部塞进实体字段：

- 政权—政权：前身、后继、分裂、合并、征服、臣属、册封、竞争、并存。
- 政权—地点：直接控制、间接控制、军事占领、政治影响、文化影响、争议范围。
- 政权—都城：正式都城、实际中心、次级都城、季节性都城、临时驻地、军事中心、移动汗廷、候选都城。
- 政权—人物：创建、统治、任职、反抗、效忠、册封、敌对、后世归类。
- 政权—遗产：建造、使用、修缮、毁坏、继承、纪念。
- 人物—人物：血缘、婚姻、君臣、师生、同盟、政敌、继承、军事上下级。
- 人物—地点：出生、任职、活动、战争、会盟、流放、死亡、葬地、后世纪念。
- 地点—遗产：遗址所在、文物出土、碑刻关联、纪念地点。
- 事件—实体：发生地、参与者、发动者、受影响政权、结果和后续影响。
- 史料—断言：记载、支持、反驳、推测、考古支持、后世解释。

## 时态与断言

所有重要关系都应支持：

```ts
interface HistoricalClaim {
  id: string;
  subjectId: string;
  predicate: string;
  objectId?: string;
  validFrom?: number;
  validTo?: number;
  datePrecision: 'day' | 'year' | 'approximate' | 'range' | 'century' | 'unknown';
  perspective: 'polity' | 'city' | 'person' | 'heritage' | 'source' | 'overview';
  evidenceType: 'explicit-record' | 'archaeology' | 'cross-checked' | 'inference' | 'tradition';
  confidence: 'high' | 'medium' | 'low';
  sourceIds: string[];
  uncertaintyNote?: string;
}
```

必须区分：事件发生时间、政权有效时间、都城使用时间、人物生命时间、遗址使用时间、史料成书时间和现代研究确认时间。

系统必须允许同一年多个政权并存、同一政权多个政治中心、人物跨越多个政权、地点被不同政权先后使用，以及改国号与权力转移不同步。

## 长安城市史 MVP

首个纵向试点选定“长安/西安”城市视角，围绕一座城市构建完整闭环：

- 政权：秦、西汉、新、前赵、前秦、后秦、西魏、北周、隋、唐等。
- 事件：建都、迁都、改名、战争、政变、制度改革和政权更替。
- 人物：统治者、重要臣僚、军事人物、思想人物和与城市密切相关的人物。
- 遗产：城址、宫城、陵墓、寺观、碑刻、考古遗址和现代博物馆。
- 史料：编年史、地方志、考古资料和现代研究，支持来源对照。

首个闭环必须支持：

```text
政权 ↔ 首都 ↔ 长安/西安 ↔ 人物 ↔ 事件 ↔ 遗产 ↔ 史料
```

## 时间刻度驱动的地图状态

山河年轮中的地图是按时间刻度呈现某一时期空间形态的历史地图。用户选定年份后，地图查询并呈现该年份有证据支持的疆域、政治中心、历史地点和事件状态。年份是查询切片，不代表所有史实均精确到该年；实体存续、疆域几何可用、地点可定位和资料覆盖是不同状态，必须分别表达。

- 疆域只按明确的有效区间或精确断面呈现。只在来源支持稳定时段模型时才使用区间几何，并标示这是来源时段表达，不声称逐年独立考证。
- 不跨缺年插值、复制邻年形状或默认保留上一帧。`leave-unfilled`显示为“该时段缺少足够地图证据”，不能解释为政权或历史活动不存在。
- `maximum` 轮廓仅作为明确标注的范围参考，默认不与当年实况混同；研究视角应能够区分实际控制、名义主张、军事占领、间接影响、文化影响和争议范围。
- 同一时期允许多个政权、多个政治中心和重叠主张并存。政权存在但无疆域几何时仍可通过时间轴或目录查看，不因地图缺图而从历史叙述中消失。
- 城市位置、古城范围、现代城市位置和遗址范围是不同空间对象。证据只支持点位或区域时，不绘制精确城界；古代范围不得由现代行政边界反推。
- 事件路线必须区别于疆域，说明阶段、方向、起讫位置和定位精度。事件地点是确址、候选位置或区域描述，应可区分。

地图时间轴要将三种时间标记分开表达：①疆域资料断面/资料变化，回答“何处有可用地图资料”；②历史事件/事件阶段，回答“何时发生了历史过程”；③政权存续与都城/政治中心阶段。标记具有不同样式和说明，不把资料更新时间误作历史转折。点击事件标记先显示其时间精度和关联对象；“定位到事件时期”由用户明确触发后才改变地图年份。

地图图例随当前年份、疆域口径和可见图层更新，说明线型/填色的历史语义、时间精度、证据状态及资料覆盖。图层按疆域及控制语义、都城/政治中心、历史地点、事件/路线、现代地理参照等任务分组，并显示当前时点可用与缺失状态。颜色不能作为唯一的语义编码。

## 地图对象选择与专题入口

点选地图对象先选中并高亮对象，地图年份和镜头不变，再展示与当前地图年份相关的上下文卡。卡片顺序为：对象名称与当前状态、与当前地图/选中上下文的关系理由、资料覆盖和证据状态、少量高价值的继续学习入口。它是专题入口，不替代完整专题文章。

- **疆域/边界**：显示政权、控制/主张语义、适用时间、几何类型（精确断面/来源时段/范围参考/争议或缺失）、来源与不确定性。
- **政权**：显示当前是否存续、疆域资料状态、当前政治中心、同期并存政权和关键事件入口。
- **城市/地点**：显示历史名称、当前时期角色、现代地点映射及定位精度；只显示由有时间和空间依据的关系连接的人物与事件。
- **都城/政治中心**：显示所属政权、中心角色、有效时期、并存中心和证据，不把中心压成单值 `capitalPlaceId`。
- **事件/路线**：显示日期精度、阶段、参与政权/人物、发生地点定位精度和事件证据；长时段过程按阶段呈现。

选中对象、打开专题、地图定位、改变年份和进入比较模式是不同操作。专题下钻默认保留地图年份；“在当前地图定位此地”只改变镜头，“查看此事发生时的地图”才切换年份，“比较前后时期”才进入对比。关系入口必须显示可理解的理由，例如“此城在该时期是该政权都城”或“此人在该事件中担任决策者”。不得因同朝代、同时代、同地或同事件自动推定关系或因果。

地图年份、时间轴窗口、对象完整历史范围、专题章节时期、当前选中对象和专题阅读位置相互独立。所有下钻路径均可返回，并恢复年份、时间轴窗口、地图相机、图层、选中对象、专题章节和滚动位置。地图渲染年份尚未追上时间游标时应有同步状态，不显示成已完成的年份切换。

## 产品交互

- 时间轴：展示当前时间点的政权、人物、都城、事件和遗产。
- 政权页：展示建立—发展—衰亡链路和相关人物/城市/事件。
- 城市页：展示城市历代政治角色、历史名称和遗产沿革。
- 人物页：展示生平、任职、关系网络和活动地点。
- 遗产页：展示历史使用期、现存状态、相关人物和事件。
- 史料抽屉：展示来源、证据类型、成书时间、冲突说法和项目解释。

视角切换时，界面必须同时显示当前观察对象、时间范围、关系过滤器、史料范围和地图语义。

### 学习入口与内容组织

产品目标是辅助历史爱好者学习历史。知识图谱需要支持多角度、多层次的学习入口，不以堆叠实体数量或无目的浏览关系图为目标。除政权、城市、人物、遗产和史料外，事件应有独立的学习视角；政策/制度也应作为独立知识对象建模，不仅作为事件的附属文本。

- **政权视角**：建立背景与关键事件、建立者和重要人物、首都及迁都、政治结构、政策、战争与并立政权、疆域变化、终结与影响。
- **城市视角**：历史名称、各时期政权与政治角色（都城、陪都、军事中心或地方中心）、关键事件、活动人物及今日可见遗址。历史地点与现代城市通过有证据的映射关联，不因名称相同而自动合并。
- **人物视角**：基本身份、生平阶段、任职与活动地点、参与事件、亲属/君臣/师承/联盟/对立等关系、史料评价及年代不确定性。不得把同朝代、同时代或共同参与事件自动推断为人物关系。
- **事件视角**：背景、参与者、发生地点与路线、事件阶段、直接结果、后续影响、相关政策、不同政权视角、史料和争议。因果关系必须有依据或标为研究解释，不能仅由时间先后推导。
- **政策/制度视角**：要解决的问题、提出与决策者、政策内容、执行机构和执行者、实施地区、受影响群体、执行过程、效果、长期影响及调整/争议；明确区分提出、颁布、实际执行、地方执行和后续影响。
- **遗产视角**：今日名称与位置、历史用途、建造/重建/改建、相关政权/人物/事件、现存部分、考古结论、后世修复与争议。区分原物保存、后世重建、遗址位置、历史记载、推测性复原和现代纪念性建筑。
- **史料视角**：呈现材料自身信息、成书/发现时间、来源类型、支持或反驳的断言、相互冲突之处及项目采用的解释。

每种详情以经过编辑的专题阅读内容组织，而非数据表或卡片堆叠。重要事实、研究解释、争议、来源和资料空白应有稳定且易辨识的呈现方式；图注、地点、时间和来源紧邻对应内容。地图纹理不作为长文阅读背景。

### 探索路径与时间状态

每次下钻都要说明关联理由，例如“此人在该事件中担任主要决策者”或“该城是该政权在这一时期的都城”。关联对象可切换阅读，但地图定位、切换时期和返回操作应分别表达；返回上一项应恢复之前的实体、章节、地图状态和阅读位置。

产品应维护并分别展示以下时间状态，避免互相隐式覆盖：

1. 地图当前年份。
2. 时间轴显示范围。
3. 当前阅读对象的完整历史范围。
4. 当前章节对应的历史时期。

从地图节点打开人物或政权详情时可定位到相关章节，但仍可阅读该对象的完整历史；点击人物或事件不应悄悄改变地图年份。未知年代标注为“年代未明”；缺少结束时间不等于持续至今。界面始终可识别当前阅读对象、阅读时期、当前地图年份、证据入口和返回路径。

首条端到端学习路径为：进入城市 → 查看历代政权变化 → 选择时期 → 阅读关键事件 → 查看参与人物 → 查看相关政策 → 定位历史地点 → 查看今日遗产 → 返回城市时间线。验收关注学习路径是否连贯、关联是否可解释、状态是否可预期、证据与不确定性是否清楚，以及用户能否回到原阅读位置。

### 关系图与设备适配

不采用一个不分问题的通用关系网络。根据学习问题选择家族树、分阶段政治关系图、城市政权时间线、事件阶段与行动路线、政策执行关系图或对象中心关系图。综合探索默认只展示当前对象的一层关系，用户主动展开后才显示第二层；每条关系可查看方向、类型、适用年代、解释、证据、不确定性和继续阅读入口。窄屏默认用按关系类型分组的清单，图形网络作为可选视图。

详情阅读需响应 PC、平板横竖屏、手机及低高度窗口。宽屏可并列地图和阅读区，窄屏以清晰的分步阅读与分组关系清单完成同一条学习路径；触控入口需易于操作，来源和说明不得依赖悬停才能访问。

### 地图与专题的响应式分栏

用户从地图对象进入相关专题后，在可用宽度足够的屏幕上使用工作台双栏：地图栏持续保留当前历史地图，专题栏显示完整阅读内容。专题进入不应把地图替换成全屏文章，也不应把专题继续压缩成仅适合短摘要的抽屉。两栏之间设置可拖动分隔条，初始比例约为地图 55%、专题 45%，并设置地图和阅读区的最小可用宽度；实际启用条件以工作区可用宽度和内容可读性为准，不只依赖设备型号或单一固定断点。

分隔条应具备清晰的拖动提示、足够的指针和触控命中区域、键盘调整能力及可访问的分隔条语义。拖动时地图应及时适配新尺寸；调整比例不得改变地图年份、镜头、图层、选中对象或专题滚动位置。可提供收窄/展开专题栏的快捷操作，并记住用户本次工作台中的宽度偏好。

当屏幕宽度或高度不足以同时保证地图辨读和正文阅读时，布局应切换为单主视图：专题以全屏或近全屏阅读呈现，保留明确的返回地图操作；返回后恢复进入专题前的地图、时间轴、图层、相机、选中对象和阅读位置。中等宽度设备允许双栏但提供可调比例；平板横屏优先双栏，平板竖屏根据实际可用宽度选择双栏或单主视图；手机竖屏默认单主视图，可在地图和专题间往返，手机横屏或足够宽的折叠屏/小窗口可启用紧凑双栏。低高度窗口须保证专题滚动区与地图操作区仍可访问，不因固定页头/时间轴挤掉正文。

专题栏采用专业文章式排版：标题、时期与关联理由、导读、分节正文、证据与延伸入口层级清楚，正文宽度和行距适合长文阅读，不以连续卡片替代叙述。图像、史料影像、地图/路线图、视频和音频等多模态材料嵌入相关章节并有图注、出处和权利信息；图片提供替代文本，视频提供字幕，音频提供文字稿，不自动播放。

专题与地图之间的操作必须显式区分：

- “在当前地图定位此地”只移动地图镜头，不改变地图年份。
- “查看此事发生时的地图”明确切换至指定年份或时期。
- “比较前后时期”明确进入时点比较模式。
- 返回专题或地图时恢复原阅读章节/滚动位置和完整地图状态。

响应式验收应覆盖宽屏桌面、窄窗口桌面、平板横屏、平板竖屏、手机竖屏、手机横屏及低高度窗口；各形态均应完成“选中地图对象—进入专题—地图定位/时期切换—返回原位置”的闭环。不能只以组件未溢出作为通过标准，还需确认地图可辨读、正文可连续阅读、触控和键盘可操作、状态可恢复。

### 内容质量与审核状态

每个核心实体及关系应记录名称/别名、时间与空间范围、关系方向、来源及来源类型、证据强度、不确定性、适用视角和审核状态。内容状态至少区分：`draft`（已整理、待核验）、`source-checked`（有明确来源）、`cross-checked`（经多来源或专家交叉核验）。界面应分别表达史料直接记载、后世研究结论、项目整理解释、尚有争议和暂无足够资料；“暂无资料”表示项目当前未收录，不表示历史上不存在。

## 内容数据与存储架构约束

内容、领域规则和呈现代码必须分层。实体、断言/关系、叙事章节、别名、来源及媒体资源作为可独立校订和校验的内容数据维护；组件和业务模块经稳定的数据访问接口读取，不把史实写成组件常量或依赖具体文件路径。政策/制度、人物关系、遗产沿革和事件阶段等具有独立生命周期的内容应有自己的对象或关系记录。

当前阶段可继续用 TypeScript/JSON 文件存储，采用文件适配器满足现有规模。应维持实体与关系的稳定 ID、明确 schema、引用完整性校验、数据版本和迁移约定。长篇叙述、图片、地图几何、扫描件等可存入独立文件/对象存储，由结构化记录通过稳定资源 ID 或受控 URI 引用，并记录来源、权利/许可、校验值和版本。未来可将结构化实体、关系、索引迁入数据库；存储迁移不要求重写学习视图和领域规则，也不预设特定数据库产品。是否迁移由协作编辑、数据规模、检索和并发写入需求决定。

## 历史表达边界

- 名义统治、实际控制、军事占领、朝贡/册封、间接影响和文化影响不能共用一种疆域表达。
- 游牧政权的移动汗廷不能自动转换成固定首都。
- 现代城市不能简单等同于古代城市实体。
- 考古文化、遗址和现代遗产认定不能直接证明完整政权疆域。
- 后世人物形象、文学叙事和同时代史料必须分层显示。
- 史料空白、定位不明、学界争议和项目未核验必须分别标记。
- “未解决”本身是历史学习内容，不应被隐藏为单一确定答案。

## 实施路线

### P0：知识底座

- 新增 `Person`、`HeritageAsset`、`HistoricalClaim` 类型。
- 将首都沿革、事件地点和疆域证据统一纳入断言式关系模型。
- 保留现有 TypeScript 数据作为第一阶段存储，不立即引入图数据库。
- 建立实体 ID、别名、来源和时态校验。

### P1：长安城市史闭环

- 完成 3—5 个关键政权、10—20 个事件、20—40 个人物关系和 10 个左右遗产节点。
- 实现政权视角与城市视角切换。
- 实现地图、时间轴、关系面板和史料抽屉联动。

### P2：扩展与复用

- 复制同一模型到洛阳、南京、北京、成都等城市。
- 增加人物关系网和遗产专题。
- 支持观点并列、史料冲突和教师/研究型阅读模式。
- 在数据规模确实超过 TypeScript 数据可维护范围后，再评估图数据库或 RDF 导出。

## MVP 验收标准

1. 用户可以从长安城市页进入任一关联政权。
2. 用户可以从政权页回到其首都、事件、人物和遗产。
3. 迁都、改名、并立和时间重叠不会被压成单一静态关系。
4. 每条关键结论都能打开来源和不确定性说明。
5. 人物关系能按时间和关系类型筛选。
6. 遗产页面能区分历史状态、遗址状态和现代展示状态。
7. 同一事实在政权视角和城市视角下可以得到不同但相互关联的叙述。
8. 测试能够发现悬空实体、无来源断言、反向时间区间和缺少视角的关系。
