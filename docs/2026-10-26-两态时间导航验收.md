# 山河年轮两态时间导航验收

验收日期：2026-10-29  
验收环境：本地 Vite 开发服务器、ChatGPT 内置浏览器、真实 DOM 与浏览器布局测量  
验收范围：时间探索栏、时间分析面板、真实分栏、短屏独占、键盘与触控可达性、地图状态恢复

## 结论

两态时间导航已达到本轮设计目标：默认状态只保留播放、前后一年、年份快速浏览与“打开时间轴”；分析状态承载范围、朝代、注记、精确年份及高级布局工具。时间控制器始终属于地图栏，宽屏专题分栏不会被时间轴跨越；短屏分析状态会独占工作区，关闭后恢复原地图年份、镜头相关 DOM 状态与操作焦点。

地图目录、事件搜索、“更多”面板与时间分析现在由工作台统一协调，任一临时面板打开时会关闭另一个，不再出现视觉隐藏但 `aria-expanded` 仍为真的矛盾状态。

所有尺寸均验证：页面无横向溢出；时间控制器没有进入专题栏；关闭分析前后地图年份与最终渲染年份一致。

## 真实分栏

- 1440×900 打开“唐”专题时，地图栏为 805.41px，分隔线为 1px，专题栏为 633.59px，三者是工作台的直接同级子节点。
- 使用分隔线键盘 `End` 后，地图栏精确收敛到最小宽度 560px，专题栏为 879.98px；在此宽度下时间分析自动使用 `narrow`，不会出现悬浮操作。
- 1024×768 打开专题时，地图栏 560px、专题栏 463.97px，仍为真实分栏。
- 809×934 打开专题时，专题使用完整 809×934 主视图，地图暂时隐藏；关闭详情后地图与时间导航恢复。
- 打开、下钻、关闭专题均未改变所选年份、地图渲染年份、时间范围或图层选择。

## 交互与无障碍

- 844×390 短屏中，打开分析后的键盘顺序从“打开时间轴”进入“关闭时间分析、范围预设、朝代选择、注记、精确年份”等分析控件；地图背景不会进入 Tab 顺序。
- `Escape` 和关闭按钮均关闭分析；关闭后焦点返回“打开时间轴”，地图容器由 `display:none` / `inert` 恢复为可见和可操作。
- 时间滑块提供可读的 `aria-valuetext`，例如“800年”“803年”。
- 播放期间没有逐年创建 `aria-live` 或 `role=status` 通告，避免读屏器连续播报年份。
- 注记默认值为“无”，事件标记与资料变化节点在未选择时不挂载，而非仅视觉隐藏。
- 通用按钮、输入框、选择框、滑块和步进控件的可触达高度均不小于 44px。按历史跨度比例绘制的朝代带保持 27px 高和可变宽；其完整等价操作由 44px 高的朝代选择框提供。

## 临时面板互斥

实际浏览器在 1024×768 下验证：

1. 打开当前历史状态后，目录存在，`aria-expanded=true`。
2. 点击“打开时间轴”后，目录卸载，`aria-expanded=false`，时间分析存在。
3. 再次点击当前历史状态后，时间分析卸载，目录重新打开，`aria-expanded=true`。

该行为替代了原先使用 CSS 隐藏临时面板的方案，确保可见状态、DOM 状态和辅助技术状态一致。

## 验收中发现并修复的问题

1. 时间探索滑块及部分分析控件只有 24—35px：统一提升到至少 44px，并增加组件断言。
2. 时间分析与目录、事件搜索、工作台面板可能重叠：将分析状态提升为可控工作台状态，实现双向互斥。
3. 809×934 竖屏平板被误判为宽屏并出现悬浮工具：尺寸分类加入纵横比判断，改为 `narrow`。
